## 1. Общая схема

```text
xlsx токограмма I(t)
        │
        ▼
  чтение + dt                          [Блок 1]
        │
        ▼
  фильтрация → период → циклы          [Блок 2]
        │
        ▼
  cycle_index: best                    [Блок 3]
        │
        ├──────────────────────────────┐
        ▼                              ▼
  кинематика S,v,a                ток I_aligned
  (API C-640)                     → P(I) → P_par → P_net
        │                              │
        │                              ▼
        │                         F_head = P_net / (k_tf · v)
        │                              │
        ├──────── pump_load ───────────┤
        ├──────── m_eq·a ──────────────┤
        ├──────── Гук (выкл.) ─────────┤
        │                              │
        │              wave_model=true │
        │                              ▼
        │                    PDE Гиббса → F_surface
        │                              │
        └──────────────┬───────────────┘
                       ▼
              F = F_surface + F_fluid + F_inertia (+ …)
                       │
                       ▼
              динамограмма (S, F) + метрики vs эталон
```

**Итоговая формула силы для текущего конфига** (`wave_model: true`, `elastic.enabled: false`, `friction.mode: none`):

\[
F(t) = F_{\mathrm{surface}}(t) + F_{\mathrm{fluid}}(t) + F_{\mathrm{inertia}}(t)
\]

где \(F_{\mathrm{surface}}\) — устьевая упругая сила из волновой модели, \(F_{\mathrm{fluid}}\) — гидравлический профиль, \(F_{\mathrm{inertia}} = m_{\mathrm{eq}} a\).

## 3. Блок 1. Чтение токограммы

**Модуль:** `src/io_tokogram.py` → `read_tokogram`  
**Параметры:** `tokogram.dt_seconds`, файловый xlsx

### 3.1. Структура файла

Согласно ТЗ (раздел Д.1), лист Excel без построчного заголовка:

| Колонка | Содержимое |
|---|---|
| A | Метка времени (первая распознанная ячейка), формат `%d.%m.%Y %H:%M` |
| B | Ток \(I\) [А], начиная со строки данных |
| C | Дискретность \(\Delta t\) [с] (если заполнена) |

Чтение:

1. Ток берётся из колонки B до первого NaN.  
2. Хвостовые нули отбрасываются (служебные).  
3. Дискретность: из колонки C, иначе из конфига.

### 3.2. Параметр \(\Delta t\)

\[
\Delta t = 0{,}2~\mathrm{с} \quad (\texttt{tokogram.dt_seconds})
\]

| Параметр | Тип | Откуда |
|---|---|---|
| \(\Delta t\) | **исходный (допущение)** | Конфиг; в файле скв. 16427 колонка «Дискретность» пуста → предупреждение Ж.1 |

Физический смысл: шаг дискретизации регистрирует ток с частотой \(f_s = 1/\Delta t = 5\) Гц. Вся дальнейшая кинематика и волновая модель наследуют этот шаг (через период цикла \(T = n\cdot\Delta t\)).

### 3.3. Результат блока

Массив \(I[k]\), \(k=0,\ldots,N_{\mathrm{tok}}-1\), метка времени токограммы, `dt_source = "config"`.

## 4. Блок 2. Автоматическая сегментация

**Модуль:** `src/segmentation.py` → `segment_tokogram`  
**Конфиг:** секция `segmentation`

Цель — разбить длинную запись тока на отдельные **циклы качания** (впадина → впадина) и оценить период \(T\).

### 4.1. Фильтр 1. Сглаживание Савицкого–Голея

\[
I_{\mathrm{sm}}[k] = \mathrm{SavitzkyGolay}\bigl(I;\, w,\, p\bigr)
\]

| Параметр | Значение | Тип | Смысл |
|---|---|---|---|
| `smoothing_window` \(w\) | 7 | исходный | Ширина окна (нечётное число отсчётов) |
| `smoothing_polyorder` \(p\) | 2 | исходный | Степень локального полинома |

**Физика / обработка сигналов:** метод приближает ток локальным полиномом и подавляет высокочастотный шум измерения без сильного сдвига фаз пиков. Нужен для устойчивого поиска впадин: сырой ток имеет «зубья» ШИМ/наводок, которые дают ложные экстремумы.

### 4.2. Фильтр 2. Оценка периода по автокорреляции (ACF)

Центрирование:

\[
\tilde{I} = I_{\mathrm{sm}} - \overline{I_{\mathrm{sm}}}
\]

Автокорреляция:

\[
R[\ell] = \sum_k \tilde{I}[k]\,\tilde{I}[k+\ell]
\]

Нормировка \(R[\ell]/R[0]\). Период ищется как лаг максимума на окне, согласованном с допустимой частотой качаний:

\[
\ell_{\min} = \left\lfloor \frac{60}{\Delta t\cdot \mathrm{SPM}_{\max}} \right\rfloor,\quad
\ell_{\max} = \left\lceil \frac{60}{\Delta t\cdot \mathrm{SPM}_{\min}} \right\rceil
\]

\[
T_{\mathrm{samples}} = \arg\max_{\ell\in[\ell_{\min},\ell_{\max}]} R[\ell]
\]

| Параметр | Значение | Тип |
|---|---|---|
| `spm_min` | 3.0 мин⁻¹ | исходный |
| `spm_max` | 12.0 мин⁻¹ | исходный |
| \(T_{\mathrm{samples}}\) | расчётный | результат ACF |
| \(T = T_{\mathrm{samples}}\cdot\Delta t\) | расчётный | период в секундах |
| \(\mathrm{SPM} = 60/T\) | расчётный | часто качаний |

**Физика:** один цикл качания — почти периодическая нагрузка на ЭД; автокорреляция находит доминирующий период между \(\mathrm{SPM}_{\min}\) и \(\mathrm{SPM}_{\max}\) (типовой рабочий диапазон ШГН).

Для скв. 16427 типично: \(T_{\mathrm{samples}}\approx 56{,}6\), \(T\approx 11{,}32\) с, \(\mathrm{SPM}\approx 5{,}3\).

### 4.3. Фильтр 3. Поиск впадин (границ циклов)

На сглаженном сигнале ищутся локальные **минимумы** тока как `find_peaks(-I_sm)`:

\[
\mathrm{prominence}_{\min} = f_{\mathrm{prom}}\cdot\bigl(\max I_{\mathrm{sm}} - \min I_{\mathrm{sm}}\bigr)
\]

\[
\mathrm{distance}_{\min} = (1 - m)\cdot T_{\mathrm{samples}}
\]

| Параметр | Значение | Тип |
|---|---|---|
| `prominence_fraction` \(f_{\mathrm{prom}}\) | 0.3 | исходный |
| `period_search_margin` \(m\) | 0.3 | исходный |
| Индексы впадин \(b_i\) | расчётные | границы сегментов |

При нехватке впадин — повторный поиск с `distance = 0.35·T`.

Дополнительно каждое положение впадины **уточняется параболой** по трём точкам:

\[
\delta = \frac{1}{2}\frac{y_0 - y_2}{y_0 - 2y_1 + y_2},\quad
b^{\star} = b + \mathrm{clip}(\delta, -0{,}5, 0{,}5)
\]

**Физика:** у нижней мёртвой точки / в зоне минимальной нагрузки ток ЭД минимален; впадины удобно брать как маркеры начала/конца цикла «впадина→впадина».

### 4.4. Фильтр 4 (опциональный). Уточнение границ взаимной корреляцией

Параметр `refine_by_xcorr: false` — **выключен** для 16427.  
При включении границы сдвигались бы по максимуму корреляции с шаблоном одного периода.

### 4.5. Классификация полных циклов

Сегмент между впадинами \(b_i\) и \(b_{i+1}\) считается **полным**, если:

1. Длина \(\in [0{,}8\,T,\; 1{,}4\,T]\) (порядок периода).  
2. В сегменте ровно **один** основной токовый пик:

\[
h_{\min} = \min I_{\mathrm{seg}} + f_{\mathrm{prom}}\cdot(\max I - \min I)_{\mathrm{global}}
\]

Пики: `find_peaks(I_seg, height=h_min, distance≈len/5)`.

**Физика:** полный цикл ШГН имеет один главный «горб» тока на подъёме; сегменты с 0 или ≥2 пиками — артефакты / двойные периоды.

### 4.6. Выход сегментации

- `boundaries` — массив впадин;  
- `period_samples`, `period_seconds`;  
- `full_cycle_indices` — индексы полных циклов;  
- график `output/segmentation.png`.

## 5. Блок 3. Выбор рабочего цикла

**Конфиг:** `segmentation.cycle_index: best`  
**Код:** `pipeline._select_best_cycle`

### 5.1. Кандидаты

Из всех полных циклов берутся сегменты с длиной \(\in[0{,}85\,T,\; 1{,}15\,T]\).

### 5.2. Критерий «best»

Для каждого кандидата запускается полный `process_cycle_mvp`, считается **MAPE** силы после выравнивания по фазе относительно эталона:

\[
\mathrm{MAPE} = \frac{100\%}{M}\sum_{j=1}^{M}\left|\frac{F_{\mathrm{calc}}(\tau_j) - F_{\mathrm{ref}}(\tau_j)}{F_{\mathrm{ref}}(\tau_j)}\right|
\]

Выбирается цикл с **минимальным MAPE**.

| Параметр | Тип | Комментарий |
|---|---|---|
| Индекс цикла | расчётный | Результат оптимизации по MAPE |
| Эталон \(F_{\mathrm{ref}}\) | исходный | Файл динамограммы |

**Физика:** токограмма и эталонная динамограмма сняты в разное время (см. предупреждение Ж.3); выбирается цикл, **наиболее похожий по форме** на эталон, а не обязательно тот же физический цикл.

## 6. Блок 4. Кинематика станка-качалки

**Модуль:** `src/kinematics/api_geometry.py`  
**Конфиг:** `kinematics.mode: api_geometry`, `S0_m: 3.5339`

### 6.1. Время и частота вращения кривошипа

Для цикла из \(n\) отсчётов:

\[
T = n\cdot\Delta t,\quad
\omega = \frac{2\pi}{T},\quad
t_k = k\cdot\frac{T}{n},\quad k=0,\ldots,n-1
\]

| Параметр | Значение / формула | Тип |
|---|---|---|
| \(n\) | длина выбранного цикла | расчётный |
| \(T\) | \(n\cdot 0{,}2\) с | расчётный |
| \(\omega\) | \(2\pi/T\) | расчётный |
| \(S_0\) | **3.5339 м** | **исходный** (`kinematics.S0_m`) |

### 6.2. Режим `harmonic` (в конфиге 16427 не используется, дан для сравнения)

\[
S(t)=\frac{S_0}{2}\bigl(1-\cos\omega t\bigr),\quad
v=\frac{S_0\omega}{2}\sin\omega t,\quad
a=\frac{S_0\omega^2}{2}\cos\omega t
\]

Это приближение «гармонического хода» (диссертация Яшина (2.20)–(2.22)).

### 6.3. Режим `api_geometry` (используется)

Четырёхзвенник Class I по API Spec 11E (метод в духе Svinos).  
Типовая геометрия **C-640D-305-120** (`use_default: true`):

| Звено | API-символ | Дюймы | Метры |
|---|---|---|---|
| Переднее плечо балансира | \(A\) | 155 | 3.937 |
| Заднее плечо | \(C\) | 111.09 | 2.822 |
| Шатун (pitman) | \(P\) | 133.50 | 3.391 |
| Кривошип | \(R\) | 30 | 0.762 |
| Горизонталь база–седло | \(I\) | 111 | 2.819 |
| Высота седла / вала | \(H\), \(G\) | 234, 96 | 5.944, 2.438 |

Базовое расстояние:

\[
K = \sqrt{(H-G)^2 + I^2}
\]

Вспомогательные углы крайних положений:

\[
\gamma = \arccos\frac{(R+P)^2 + K^2 - C^2}{2(R+P)K},\quad
\alpha = \arcsin\frac{I}{K} - \gamma
\]

\[
\psi_B = \arccos\frac{C^2 + K^2 - (P+R)^2}{2CK},\quad
\psi_T = \arccos\frac{C^2 + K^2 - (P-R)^2}{2CK}
\]

Геометрический ход:

\[
S_{0,\mathrm{geom}} = A\,(\psi_B - \psi_T)
\]

Угол кривошипа \(\theta\) отсчитывается от 12 часов по часовой;  
\(\theta_2 = 2\pi - \theta + \alpha\); через закон косинусов находятся вспомогательные длины/углы, затем угол балансира \(\psi(\theta)\).

Безразмерное положение полированного штока (API polished-rod position):

\[
\mathrm{PR}(\theta) = \mathrm{clip}\!\left(\frac{\psi_B - \psi(\theta)}{\psi_B - \psi_T},\, 0,\, 1\right)
\]

Масштабирование к паспортному/калиброванному ходу скважины:

\[
S(t) = \mathrm{PR}\bigl(\theta(t)\bigr)\, S_{0,\mathrm{geom}}\cdot \frac{S_0}{S_{0,\mathrm{geom}}}
\]

Начало цикла (\(t=0\)) привязано к **НМТ** (\(S\approx 0\)).

Скорость и ускорение — численным дифференцированием:

\[
v = \frac{dS}{dt}\ (\texttt{np.gradient}),\quad
a = \frac{dv}{dt}
\]

| Параметр | Тип |
|---|---|
| \(A,C,P,R,I,H,G\) | исходные (таблица API / C-640) |
| \(S_0\) | исходный (калибровка скважины) |
| \(S(t),v(t),a(t)\) | расчётные |

**Физика:** реальная кривая хода не чистый \(\cos\); укорочение шатуна и плеч даёт асимметрию подъёма/спуска, что важно для формы динамограммы и знака \(v\).

## 7. Блок 5. Мощность двигателя по току

**Модуль:** `src/motor_model.py` → `torque_from_current_simple`  
**Конфиг:** `motor.*`, `tokogram.i_phase_shift_samples`

### 7.1. Фазовый сдвиг тока

\[
I_{\mathrm{aligned}}[k] = I\bigl[(k - s)\bmod n\bigr],\quad s = 1
\]

| Параметр | Значение | Тип |
|---|---|---|
| `i_phase_shift_samples` | 1 | исходный (калибруемый) |

**Физика:** кинематика «привязана» к мёртвым точкам, а ток может быть сдвинут по фазе из‑за инерции привода / начала отсчёта сегментации. Сдвиг на 1 отсчёт (\(\approx 0{,}2\) с) — эмпирическая калибровка.

### 7.2. Полином мощности

\[
P(I) = P_0 + a\,I + b\,I^2 + c\,I^3
\]

| Параметр | Значение | Ед. | Тип |
|---|---|---|---|
| \(P_0\) = `P0_w` | 3407.04 | Вт | исходный (калибр.) |
| \(a\) = `P_a_w_per_a` | 425.348 | Вт/А | исходный |
| \(b\) = `P_b_w_per_a2` | −31.7642 | Вт/А² | исходный |
| \(c\) = `P_c_w_per_a3` | 0.566 | Вт/А³ | исходный |
| \(P(t)\) | — | Вт | расчётный |

**Физика:** вместо полной схемы Клосса / Клоссовой модели MVP использует калибруемую статическую кривую «ток → электрическая мощность», подгоняемую под скважину.

Дополнительно в моторе хранятся \(\eta_{\mathrm{ed}},\eta_{\mathrm{per}},n_{\mathrm{red}},n_{\mathrm{kp}},n_{\mathrm{sync}},s_{\mathrm{nom}}\) — для TF-пути в MVP непосредственно в \(F\) идёт \(P_{\mathrm{net}}\), а не полный крутящий момент через редуктор (см. блок 7).

## 8. Блок 6. Паразитные мощности

\[
\omega = \frac{2\pi}{T}
\]

\[
P_{\mathrm{par}}(t) = P_0^{(\mathrm{par})} + P_1\sin(\omega t + \varphi) + P_2\sin(2\omega t + \varphi_2)

| Параметр | Значение | Тип |
|---|---|---|
| `P0` | 1150.88 Вт | исходный |

**Физика:** в полной модели Яшина паразитные мощности \(P_\delta,P_R\) строятся из масс и геометрии. В MVP они заменены калибруемым рядом из 0–2 гармоник, описывающим «остаточные» потери/момент инерции во времени цикла.

| Величина | Тип |
|---|---|
| \(P_{\mathrm{net}}\) | расчётная |

## 9. Блок 7. Баланс мощности и усилие через Torque Factor

**Модуль:** `src/yashin_inverse.py` → `compute_rod_load_tf`  
**Конфиг:** `inverse.method: torque_factor`, `k_tf: 0.3608`

### 9.1. Момент на кривошипе (упрощённо)

\[
\omega_{\mathrm{кр}} = \frac{2\pi}{T},\quad
M_{\mathrm{net}}(t) = \frac{P_{\mathrm{net}}(t)}{\omega_{\mathrm{кр}}}
\]

### 9.2. Torque Factor и сила

\[
\mathrm{TF}(t) = k_{\mathrm{tf}}\cdot\frac{v(t)}{\omega_{\mathrm{кр}}}
\]

\[
F_{\mathrm{head}}(t) = \frac{M_{\mathrm{net}}(t)}{\mathrm{TF}(t)} = \frac{P_{\mathrm{net}}(t)}{k_{\mathrm{tf}}\, v(t)}
\]

| Параметр | Значение | Тип |
|---|---|---|
| `k_tf` | 0.3608 м (масштаб TF) | исходный (калибр.) |
| `interpolate_dead_points` | true | исходный |
| \(F_{\mathrm{head}}\) | Н | расчётный |

**Физика:** \(P \approx F\cdot v\) с поправочным геометрическим коэффициентом \(k_{\mathrm{tf}}\) (аналог моментального плеча / TF). Там, где \(v\to 0\) (ВМТ/НМТ), деление неустойчиво.

### 9.3. Мёртвые точки

Маска «плохих» точек:

- \(|v| < 0{,}01\cdot\max|v|\);  
- или \(|\mathrm{TF}|\) слишком мал;  
- или ±1 отсчёт около смены знака \(v\).

При `interpolate_dead_points: true` значения \(F\) в маске интерполируются **отдельно** на ветвях \(v>0\) и \(v<0\).

## 10. Блок 8. Гидравлика насоса

**Модуль:** `get_pump_load_force`  
**Конфиг:** `pump_load.mode: force_profile`

Цель — воспроизвести **разрыв петли** (разную среднюю нагрузку на подъёме и спуске), который чисто из \(P/(kv)\) получается слишком узким.

\[
F_{\mathrm{fluid}}(t) =
\begin{cases}
F_0^{\downarrow} + F_1^{\downarrow}\dfrac{S(t)}{S_0}, & v(t) < 0 \quad (\text{спуск})\\[6pt]
- F_{\mathrm{up}}, & v(t) > 0 \quad (\text{подъём})\\[6pt]
0, & v = 0
\end{cases}
\]

| Параметр | Значение, Н | Тип |
|---|---|---|
| `F0_down_n` | 25538.1 | исходный |
| `F1_down_n` | 4769.7 | исходный |
| `F_up_n` | 3576.7 | исходный |
| \(F_{\mathrm{fluid}}\) | — | расчётный |

**Физика:** на спуске штанговый насос «несёт» столб жидкости (высокая нагрузка); на подъёме часть вклада может моделироваться вычитанием \(F_{\mathrm{up}}\). Профиль линейно растёт с \(S\) на спуске.

> В текущей сборке силы при `wave_model: true` эта добавка **всё равно суммируется** с \(F_{\mathrm{surface}}\) (см. блок 13).

## 14. Блок 12. Волновая модель Гиббса

**Модуль:** `src/physics/rod_wave.py` → `solve_rod_wave`  
**Включение:** `wave_model: true`  
**Конфиг:** секция `rod_wave`

### 14.1. Уравнение

\[
\frac{\partial^2 u}{\partial t^2} + \nu\frac{\partial u}{\partial t}
= c^2\frac{\partial^2 u}{\partial x^2} + g
\]

\[
c = \sqrt{\frac{E}{\rho}},\quad
A = \pi\frac{D^2}{4},\quad
\Delta x = \frac{L}{N-1}
\]

| Параметр | Значение в 16427 | Тип |
|---|---|---|
| \(L\) | **67.0 м** | исходный |
| \(E\) | \(2.1\cdot 10^{11}\) Па | исходный |
| \(\rho\) | 7850 кг/м³ | исходный |
| \(D\) | 0.022 м | исходный |
| \(\nu\) | 0.5 с⁻¹ | исходный |
| \(N\) = `n_nodes` | 51 | исходный |
| \(g\) | 9.80665 м/с² | исходный |
| \(c\) | \(\approx 5172\) м/с | расчётный |
| \(\Delta x\) | \(L/50 = 1{,}34\) м | расчётный |
| \(\Delta t\) | \(T/n\) токограммы (~0.2 с) | расчётный |

**Физика:** \(u(x,t)\) — продольное смещение сечения колонны на глубине \(x\) (\(x=0\) — устье, \(x=L\) — низ). Слагаемое \(\nu u_t\) — линейное демпфирование; \(c\) — скорость продольной волны в стали.

### 14.2. Граничные условия (как реализовано сейчас)

**Устье (Дирихле):**

\[
u(0,t) = S(t)
\]

**Низ (Нейман):**

\[
E A \frac{\partial u}{\partial x}(L,t) = F_{\mathrm{head}}(t)
\]

где \(F_{\mathrm{head}}\) — сила из блока 7 (TF-инверсия по току).

> **Методологическое замечание.** Строгая прямая задача Гиббса ставит на низ *нагрузку насоса*, а не устьевую силу из баланса мощностей. В текущем коде в нижнее ГУ подаётся именно \(F_{\mathrm{head}}\) из TF; параметр \(L=67\) м в конфиге — следствие настройки под эту постановку. Для глубоких скважин (\(L\sim 10^3\) м) постановка ГУ должна быть пересмотрена.

### 14.3. Численная схема

Неявная конечно-разностная схема 2-го порядка по \(x\), решение трёхдиагональной системы (`scipy.linalg.solve_banded`) на каждом шаге по времени.

Обозначения:

\[
r = \frac{c^2\Delta t^2}{\Delta x^2},\quad
\alpha = 1 + \tfrac12\nu\Delta t + 2r,\quad
\beta = 1 - \tfrac12\nu\Delta t
\]

Для внутренних узлов неизвестны \(u_1,\ldots,u_{N-1}\) (\(u_0 = S\) задано).  
На нижнем конце используется **ghost-узел** для аппроксимации \(u_x(L)\).

Начальное условие:

\[
u(x,0)=S(0),\quad u(x,-\Delta t)\approx S(0)-\Delta t\, v(0)
\]

### 14.4. Постобработка — устьевая сила

Деформация (центральная / односторонняя на краях):

\[
\varepsilon = \frac{\partial u}{\partial x}
\]

На устье (одностороннее \(O(\Delta x^2)\)):

\[
\left.\frac{\partial u}{\partial x}\right|_{x=0}
= \frac{-3u_0 + 4u_1 - u_2}{2\Delta x}
\]

\[
F_{\mathrm{surface}}(t) = E A \left.\frac{\partial u}{\partial x}\right|_{x=0}
\]

| Величина | Тип |
|---|---|
| \(u(x,t)\) | расчётная |
| \(F_{\mathrm{surface}}\) | расчётная — **новая упругая составляющая устья** |

При `save_u: true` поле сохраняется в `output/rod_wave_u.npz`, строятся графики распространения волны и сравнения \(F_{\mathrm{head}}\) vs \(F_{\mathrm{surface}}\).

## 15. Блок 13. Сборка итоговой силы

**Код:** `process_cycle_mvp`

### 15.1. При `wave_model: true` (текущий конфиг)

\[
F_{\mathrm{dyn}} := F_{\mathrm{head}} \quad\text{(сохраняется для диагностики)}
\]

\[
F_{\mathrm{surface}} := \bigl(EA\,u_x(0)\bigr)_{\mathrm{wave}}
\]

\[
F(t) =
F_{\mathrm{surface}}(t)
+ F_{\mathrm{elastic}}(t)
+ F_{\mathrm{fluid}}(t)
+ F_{\mathrm{inertia}}(t)
+ F_{\mathrm{friction}}(t)
\]

Для 16427: \(F_{\mathrm{elastic}}=0\), \(F_{\mathrm{friction}}=0\), поэтому

\[
\boxed{F(t) = F_{\mathrm{surface}}(t) + F_{\mathrm{fluid}}(t) + m_{\mathrm{eq}}\,a(t)}
\]

### 15.2. При `wave_model: false`

\[
F_{\mathrm{surface}} \equiv F_{\mathrm{head}} = F_{\mathrm{dyn}}
\]

дальше та же сумма. Это режим калиброванной «жёсткой» MVP-модели без PDE.

### 15.3. Динамограмма

\[
\mathrm{Card}:\quad \bigl(S(t),\, F(t)\bigr)
\]

Сила внутри расчёта — в **ньютонах**; на графиках делится на \(g=9.80665\) → **kgf** (`units.force_unit: kgf`).

## 18. Выходные файлы и описание графиков

После прогона пайплайна в каталоге `output/` появляются картинки и служебные файлы. Ниже — **что на каждой картинке**, простыми словами. Графики `dynamogram_overlay.png` и `force_vs_phase.png` строятся через **seaborn** (`sns.lineplot`).

### 18.1. `segmentation.png` — как нарезана токограмма

- **Оси:** по X — время (с), по Y — ток двигателя \(I\) (А).
- **На графике:** чёрная кривая тока; цветные полосы — найденные циклы «впадина → впадина»; ярче залиты **полные** циклы (ровно один токовый пик); красные пунктиры — границы циклов.
- **Смысл:** проверка, что программа правильно нашла периоды качалки и из какого куска тока берётся динамограмма.

### 18.2. `dynamogram_overlay.png` — классическая динамограмма

- **Оси:** по X — ход штока \(S\) (м), по Y — сила \(F\) (kgf).
- **На графике:** синие кривые — **эталон** (измеренная динамограмма скважины); красные — **расчёт** модели. Обычно сплошная линия — подъём (↑), пунктир — спуск (↓).
- **Смысл:** привычная «коробка» динамограммы. Сравнивают форму петли, верх/низ силы и углы. Это **не** график «сила против времени».

### 18.3. `force_vs_phase.png` — сила против фазы цикла

Это **другой способ** сравнить ту же пару «эталон / расчёт», не в координатах \((S, F)\), а вдоль **прогресса цикла**.

#### Что такое «фаза» \(\tau\)

Полный ход качалки — замкнутая петля в плоскости \((S, F)\). Чтобы сравнивать силы «точка в точку», петлю «разворачивают» вдоль её длины:

\[
\tau \in [0, 1]
\]

- \(\tau = 0\) — условное начало цикла;
- \(\tau = 0{,}5\) — примерно середина пути по периметру петли;
- \(\tau = 1\) — конец того же цикла (совпадает с началом по смыслу).

Важно: **\(\tau\) — это не время в секундах**. Это нормированный путь вдоль контура динамограммы (фаза цикла). Поэтому файл называется *force versus phase* — «сила против фазы».

#### Что нарисовано

| Кривая | Цвет | Что это |
|---|---|---|
| Эталонная \(F(\tau)\) | синяя сплошная | сила эталонной динамограммы после перевода в \(\tau\) |
| Расчётная \(F(\tau)\) | красная пунктир | сила модели после перевода в \(\tau\) и **подгонки по фазе** |

**Оси:**

- X — фаза \(\tau\) от 0 до 1;
- Y — сила \(F\) (в единицах после подготовки валидации; сравниваются формы кривых).

#### Зачем «выравнивание по фазе»

Эталон и расчёт могут быть слегка **сдвинуты** друг относительно друга (цикл начинается не с той же точки контура). Перед сравнением расчётную \(F(\tau)\) циклически сдвигают так, чтобы RMSE к эталону был минимален. Именно это написано в заголовке графика: *«F(τ) после выравнивания по фазе»*.

Без такого сдвига одна и та же форма петли давала бы завышенную ошибку только из‑за другого «нуля» цикла.

#### Чем это отличается от `dynamogram_overlay.png`

| | `dynamogram_overlay.png` | `force_vs_phase.png` |
|---|---|---|
| Что видите | петля \(S\)–\(F\) | два графика \(F\) вдоль \(\tau\) |
| Удобно для | формы «коробки», углов, \(F_{\max}/F_{\min}\) | ошибки силы вдоль цикла |
| Связь с метриками | RMSE по ветвям ↑/↓ в плоскости \(S\)–\(F\) | RMSE / MAPE \(F(\tau)\) в `metrics.json` |

Если линии на `force_vs_phase.png` почти совпадают — модель хорошо попала в силу **по ходу цикла**. Если на динамограмме петли похожи, а здесь есть большие расхождения — часто виден сдвиг или локальные «пики/провалы» силы.

### 18.4. `metrics_summary.png` — таблица чисел

Не кривые, а таблица: RMSE/MAPE \(F(\tau)\), RMSE по ↑/↓, отношение \(F_↓/F_↑\), площади петель, \(dt\), SPM и т.д. Быстрый снимок качества без открытия JSON.

## 19. Ограничения текущей постановки

1. **\(\Delta t=0{,}2\) с — допущение** (не из файла).  
2. **Токограмма и эталонная динамограмма** разнесены по времени → сравнение формы, не одного физического цикла.  
3. **Нижнее ГУ волны** питается \(F_{\mathrm{head}}\) из TF-модели (устьевая оценка), а не отдельной моделью плунжера.  
4. **\(L=67\) м** в конфиге — настроечный параметр текущей связки GУ, не обязательно глубина подвески насоса.  
5. **Линейное демпфирование** \(\nu u_t\); субдискретизация волны под \(dx/c\) не выполняется.  
6. **Гук и трение** в конфиге выключены; гидравлика и инерция добавляются поверх \(F_{\mathrm{surface}}\).  
7. Режим `config.yaml` (полная legacy-модель Яшина, `model.mode: full`) — другой путь; данный документ относится к **MVP + wave** по `config_well16427.yaml`.
